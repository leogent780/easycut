# 프로세스 2: 텀 제거 + 배속 + 참고영상 스타일 자막 더빙

`samples/xhs_dish_brush_ko_dub/`(프로세스 1)에서 만든 기본 더빙 쇼츠를, 실제 잘 나가는
쇼츠들의 편집 리듬에 맞춰 한 단계 더 다듬은 버전. 여기 담긴 4단계는 전부 `shorts_factory/`
아래 정식 파이프라인 코드로 편입 완료됐고(§코드 위치 참고), 이후 실제 프로덕션에서 여러 번
검증하며 아래에 적힌 것보다 더 다듬어졌다 — 이 문서는 그 최신 상태를 반영한다.

## 산출물 (이 샘플 자체는 최초 검증 당시 스냅샷)

- `final_shorts.mp4` — 최종 쇼츠 (1080x1920, 19.8초)
- `hook_banner.png` — 상단 후킹 배너 (프로세스 1과 동일)
- `caption_template.html` — 자막 스타일 템플릿. **주의**: 이 샘플은 초기 버전(검정 텍스트 +
  흰 테두리, Pretendard Black 62px)이고, 현재 코드의 실제 자막 스펙은 아래 §자막
  스타일(현재 코드 기준)이 최신이다.

## 프로세스 1 대비 추가된 4단계

### 1. TTS 무음 구간 제거
`ffmpeg -af silencedetect=noise=-30dB:d=0.15`로 나레이션 음성의 문장 사이 텀을 전부 찾아내고,
그 구간에 해당하는 영상+음성을 통째로 잘라내는 방식(점프컷)으로 이어붙임. 문장 사이 공백이
없어지면서 훨씬 타이트한 템포가 됨.

### 2. 배속 (기본값은 더 이상 1.3배가 아님)
텀을 제거한 결과물에 영상은 `setpts=PTS/{speed_factor}`, 음성은 `atempo={speed_factor}`를
적용. **이 샘플을 만들 때는 1.3배속을 썼지만, 이후 실제 프로덕션에서 "영상이 빨리감기
되는 것 같다"는 피드백을 받고 `DEFAULT_SPEED_FACTOR`를 1.0(배속 없음, 무음 구간만 제거)으로
바꿨다** — 1.3은 이 샘플 하나를 위해 명시적으로 요청됐던 값이 일반 기본값으로 잘못
carry-over된 것이었음. 지금은 필요할 때만 `speed_factor`를 명시적으로 넘긴다.

### 3. Gemini로 문장 타이밍 정밀 정렬
TTS 결과 음성 파일을 다시 Gemini Files API에 업로드해서, 대본의 각 문장이 몇 초에
시작/끝나는지 정렬시킴. 이 타임스탬프를 1번(텀 제거)·2번(배속) 변환에 그대로 매핑해서
최종 영상 타임라인 기준 자막 타이밍을 계산 — 실제 무음 구간 데이터와 대조해서 경계를 검증함.

### 4. 참고 영상 스타일로 자막을 짧게 끊기
실제 조회수 잘 나오는 쇼츠 레퍼런스 영상 하나를 프레임 단위로 분석한 결과:
- 자막이 문장 전체를 한 번에 보여주지 않고 **2~4어절씩** 끊어서 순차적으로 노출
- 각 조각은 **0.5~1초** 정도만 보여주고 바로 다음 조각으로 전환 (겹침 없이 연속)
- (이 샘플 당시 스타일은) 검정 텍스트 + 흰색 굵은 테두리 — 현재는 §자막 스타일 참고

이 패턴대로 문장을 짧은 조각으로 나누고, 3번에서 구한 문장 경계 타이밍 안에서
글자수 비례로 각 조각의 타이밍을 배분함.

**추가로 발견/수정된 버그**: 글자수 기준으로만 조각을 자르면 "두 배는"처럼 붙어있어야 할
조사/수식어+명사 쌍이 서로 다른 자막 조각(다른 장면)으로 쪼개지는 문제가 있었다
(`두` / `배는 빨라진다고`처럼). 지금은 1~2글자짜리 짧은 단어로 조각이 끝나려고 하면 그
단어를 다음 조각의 시작으로 미루는 방식으로 고쳤다 (`dub_timing.chunk_sentence`,
`SHORT_TRAILING_WORD_MAX_CHARS`).

## 코드 위치 (정식 편입 완료)

프로세스 1 문서에 적혀있던 "아직 통합 안 된 부분"은 전부 아래로 편입 완료됐다:

- `shorts_factory/pipeline/dub_timing.py` — 무음 구간 파싱(`parse_silence_intervals`), 점프컷
  구간 계산(`compute_keep_segments`), 갭 제거+배속 후 타임스탬프 재매핑
  (`compute_gapless_speed_mapping`), 문장→짧은 자막 조각 분할(`chunk_sentence`,
  `layout_caption_chunks`) — 전부 순수 로직이라 네트워크/ffmpeg 없이 단위 테스트됨
  (`tests/test_dub_timing.py`).
- `shorts_factory/integrations/gemini_client.py` — Gemini Files API 업로드
  (`upload_file`/`wait_for_file_active`), 문장 타임스탬프 정렬(`align_sentence_timestamps`).
  일일 무료 할당량이 모델별로 따로 있다는 걸 확인하고 텍스트/TTS 각각 모델 폴백 체인을
  추가했고, 일시적 500/503/400 에러는 같은 모델로 재시도, 429(할당량 소진)는 다음 모델로
  넘어가도록 구현했다.
- `shorts_factory/pipeline/dub_caption_render.py` — Playwright로 배너/자막을 투명 PNG로
  렌더링. §자막 스타일 참고.
- `shorts_factory/pipeline/viral_translate_dub.py` — 전체 오케스트레이션. 단일 소재용
  `run_manual`과, 한 영상에 여러 제품이 들어있을 때 제품별로 대본/TTS/자막을 독립적으로
  생성한 뒤 이어붙이는 `run_manual_multi_segment` 두 가지 진입점이 있다 (§멀티 제품 확장
  참고).

## 자막 스타일 (현재 코드 기준 — 이 샘플의 caption_template.html과 다름)

이 샘플 이후 사용자가 실제 방송 자막 레퍼런스를 다시 주면서 스타일을 재조정했다:

- 배너(상단 후킹 카피)와 자막(짧은 조각) **둘 다 동일하게 Pretendard Black** 사용 (처음엔
  자막만 Do Hyeon 같은 다른 서체를 썼다가, "그냥 상단 카피랑 동일한 폰트 써라"는 피드백으로
  통일함).
- 배너는 고정 폰트 크기가 아니라 **오토핏**: 트라이얼 크기로 한 번 렌더링해서 실제 렌더링된
  너비를 측정한 뒤, 배너 폭의 86%를 채우도록 크기를 재계산해서 다시 렌더링
  (`render_hook_banner`의 `BANNER_TARGET_WIDTH_FRACTION`).
- 자막은 흰색 채우기 + 검정 얇은 외곽선(폰트 크기의 약 6.5%), 자간 -2px.

## 멀티 제품 확장 (`run_manual_multi_segment`)

한 레퍼런스 영상에 제품이 여러 개 들어있는 경우(예: "냄비뚜껑 + 주방가위" 2종 컴필레이션),
전체 영상을 한 번에 Gemini에 보여주고 대본 하나를 통으로 받으면 한국어 나레이션의 말하는
속도와 원본 영상의 편집 속도가 서로 안 맞아서 필연적으로 어긋난다 (제품이 화면에서 바뀌는
타이밍과 대본이 그 제품 얘기를 하는 타이밍이 시간이 지날수록 벌어짐). 그래서:

1. `gemini_client.detect_product_segments`로 제품별 시작/끝 구간을 먼저 찾고
2. 구간마다 원본 영상을 잘라서, 그 구간 하나만 보여주며 대본/TTS/무음제거/자막을 **독립적으로**
   생성 (`_dub_segment`) — 각 구간은 첫 번째/중간/마지막 역할에 맞는 전환구 지침을 받는다
   (마지막 구간만 확실한 마무리 문장으로 끝나도록)
3. 각 구간을 이어붙인 뒤, 전체를 아우르는 후킹 배너 하나를 씌운다

이렇게 하면 화면과 대본이 구조적으로 항상 맞아떨어진다. 또한 나레이션이 그 구간의 원본
영상 길이보다 길어질 경우, 마지막 프레임을 정지시켜(`tpad`) 화면을 늘려서 마무리 문장이
잘리지 않게 한다.

## 대본 톤/내용 관련 프롬프트 지침

`gemini_client.SCRIPT_SYSTEM_PROMPT`에 사용자가 준 실제 레퍼런스 대본 4편
(`SCRIPT_STYLE_REFERENCE_EXAMPLES`)을 요약이 아니라 **원문 그대로** 첨부해서 Gemini가 직접
톤/어미/템포를 판단하게 한다. 추가로:
- 원본 영상의 출처 국가(예: "중국", "중국 주부")를 언급하지 않도록 명시
- 첫 문장은 "다이소 가면 무조건 사야 한다는데"처럼 구체적 발견 장소 키워드로 시작하고,
  "최근 SNS에서" 같은 밋밋한 오프닝은 쓰지 않도록 명시

## TTS 프로바이더

`shorts_factory/integrations/tts_client.py`가 `gemini` / `elevenlabs` / `typecast` 세
프로바이더를 지원한다. 기본값은 `typecast`(사용자의 실제 선호 프로바이더)이며, 개발 샌드박스
네트워크 정책상 `api.typecast.ai`/`api.elevenlabs.io`에 접근이 막혀있어 두 프로바이더 모두
이 환경에서는 실제 응답을 검증하지 못했다 — 로컬 환경에서 실제 키로 테스트 필요. `gemini`
프로바이더는 이 샌드박스에서 네트워크가 열려있어 실제로 검증됐지만, 무료 티어 일일 할당량이
매우 작아서(모델당 하루 약 20회) 반복 테스트 시 자주 소진된다.
